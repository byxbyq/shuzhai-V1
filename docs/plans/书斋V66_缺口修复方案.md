## 阶段一：Prompt注入防护（P0 安全）

### 问题

#### 1.1 新增 `backend/prompt_sanitizer.py`

```python
"""Prompt注入防护：用户输入清洗 + 结构化封装 + 可配置危险词"""
import re
import json
import os

# 默认危险指令性短语（中英）——保守列表，仅拦截明确越权元指令
_DEFAULT_INJECTION_PATTERNS = [
    # 明确越权指令
    r'(?i)ignore\s+(?:all\s+)?(?:previous|above|prior)\s+instructions?',
    r'(?i)忽略(?:以上|上面|前面|之前)(?:所有)?(?:指令|提示|规则|要求)',
    r'不要遵守(?:以上|上面|前面)',
    r'(?:以上|上面的?内容?)作废',
    # 身份越权
    r'(?i)you\s+are\s+(?:now|a)\s+(?:system|admin|developer|root|DAN)',
    r'你(?:现在)?是(?:系统|admin|开发者|root|管理员)',
    r'(?i)DAN\s*模式',
    r'假装你(?:是|没有)',
    r'(?i)pretend\s+(?:you\s+are|to\s+be)',
    r'(?i)没有(?:限制|约束|filter|restriction)',
    r'(?i)进入(?:开发者|越狱|jailbreak|developer)\s*模式',
    # 提示词泄露
    r'(?i)reveal\s+(?:your\s+)?(?:system\s+)?prompt',
    r'(?i)show\s+(?:me\s+)?(?:your\s+)?(?:system\s+)?(?:prompt|instruction)',
    r'(?i)输出(?:你的)?(?:系统|原始|初始)?(?:提示词|prompt|instruction)',
    r'(?i)重复(?:你的)?(?:系统|原始)?(?:提示|prompt)',
    r'(?i)system\s*message',
    r'(?i)prompt\s*[:：]',
    # 结构化标记注入
    r'(?i)(?:system|user|assistant)\s*[:：]',
    r'(?i)</?\s*(?:system|instruction|prompt)\s*>',
    r'(?i)###\s*(?:system|系统)',
]

# 编译正则缓存
_COMPILED = None
_CONFIG_PATH = os.path.join(os.path.dirname(__file__), '..', 'data', 'sanitizer_config.json')

def _load_patterns():
    """加载默认+用户配置的危险词列表"""
    global _COMPILED
    if _COMPILED is not None:
        return _COMPILED
    patterns = list(_DEFAULT_INJECTION_PATTERNS)
    # 加载用户自定义配置
    try:
        if os.path.exists(_CONFIG_PATH):
            with open(_CONFIG_PATH, 'r', encoding='utf-8') as f:
                cfg = json.load(f)
                patterns.extend(cfg.get('extra_patterns', []))
                # 用户可禁用某些默认规则
                disabled = set(cfg.get('disabled_patterns', []))
                patterns = [p for p in patterns if p not in disabled]
    except Exception:
        pass  # 配置加载失败用默认列表
    _COMPILED = [re.compile(p) for p in patterns]
    return _COMPILED

_DATA_TAG = "user_input"

def sanitize_user_input(text, max_len=8000):
    """
    清洗用户输入用于注入Prompt（完整版：清洗+封装）。
    1. 去首尾空白
    2. 长度截断
    3. 危险指令短语替换为[已过滤]
    4. 结构化封装：<user_input>...</user_input>
    """
    if not text:
        return ""
    s = str(text).strip()
    if len(s) > max_len:
        s = s[:max_len] + "…[截断]"
    for pat in _load_patterns():
        s = pat.sub("[已过滤]", s)
    return f"<{_DATA_TAG}>\n{s}\n</{_DATA_TAG}>"

def sanitize_light(text, max_len=8000):
    """轻量清洗：仅strip+截断+过滤，不封装标签（用于已是结构化字段的场景）"""
    if not text:
        return ""
    s = str(text).strip()
    if len(s) > max_len:
        s = s[:max_len] + "…[截断]"
    for pat in _load_patterns():
        s = pat.sub("[已过滤]", s)
    return s

def reload_config():
    """重新加载配置（用户修改sanitizer_config.json后调用）"""
    global _COMPILED
    _COMPILED = None
    _load_patterns()
```

## 阶段二：E连线框画布（P1 功能缺失，最终定稿版）

### 问题

归档要求的连线框完全未实现。代码中已有的六轴关系图（只读图谱）和planning-view（Grid/Matrix/Timeline）都不是这个模块。

### 核心定位（最终定稿）

连线框不是单纯画图工具、不是正文编辑器、不是草稿页内嵌组件，是**贯穿写作全流程的「设定可视化+正文对照校验」核心工具**。全程双场景复用同一套连线数据，不重复建图、数据全局统一：

| 场景 | 时机 | 用途 |
|---|---|---|
| 前置规划场景 | 章节细纲后、写作前 | 纯规划：梳理人物关系、伏笔链条、章节因果、剧情走向 |
| 后置修改场景 | 草稿编辑阶段 | 对照校验：用规划好的连线关系，反向核对、修正正文 |

**核心原则永久不变**：连线框不自动改写正文，杜绝AI擅自篡改已写内容；但提供完整对照、定位、一键修改联动能力。

### 模块边界（彻底杜绝功能混淆）

| 工具 | 维度 | 专管 | 不做 |
|---|---|---|---|
| 连线框 | 关系维度 | 人物关系网、伏笔链关联、设定一致性对照 | 线性事件流展示 |
| 时间线（现有Step7） | 时间维度 | 事件先后、大纲执行度、伏笔状态查询 | 关系网可视化 |
| Gate | 质量维度 | 禁词、逻辑断层、人设崩塌、节奏缺失、POV漂移 | 设定一致性（让给连线框） |
| C5协作草稿 | 局部段落 | 单段正文的改写、扩写、润色 | 全局设定规划 |

- 连线框 vs 正文生成器：无自动联动，规划归规划、写作归写作；连线框仅提供AI上下文参考，必须用户主动指令才会生效
- 连线框 vs C5：连线框管全局设定校验，C5管局部段落改写，二者联动互补、互不嵌套、互不冲突
- 连线框 vs 时间线：不重复（时间线管时间顺序，连线框管关系网）；伏笔追踪轻微重叠但不冲突（时间线看状态，连线框看关联）

### 页面形态（双形态）

**电脑端（完整版，全功能）**：独立页面 + 双屏布局
- 不属于草稿页内嵌面板、不属于悬浮小窗口，从独立入口唤起
- 打开后固定左右双屏：左侧无限自由画布 + 右侧正文只读对照面板
- 双屏联动：左侧选中节点→右侧自动跳转对应正文段落；右侧浏览正文→可手动在左侧新增/修改规划节点

**手机端（精简版，仅辅助）**：独立全屏页面，无双屏布局
- 仅支持：缩放、拖拽查看全局关系图（只读）
- 禁止所有编辑操作：不能新建节点、连线、改色、删除、编辑文字
- 修改、规划统一回电脑端操作
- ⚠️ **实现随手机版大修一并落地**（见阶段四暂缓说明），当前阶段二仅实现电脑端

### 双入口设计（适配两大场景）

同一套连线数据，两个独立入口，各司其职、互不冲突：

| 入口 | 位置 | 页面形态 | 用途 |
|---|---|---|---|
| 规划入口 | 工具箱/大纲页专属入口 | 纯全屏画布，无正文面板 | 专注搭建剧情逻辑网 |
| 对照修改入口 | 草稿Tab内部「连线框对照」按钮 | 左右双屏（左画布+右正文） | 对照已规划逻辑，逐段校验修正正文 |

### source_type 作用详解

SkillPack蒸馏是把小说文本→AI提取→生成可复用写作技能包的过程。有两种输入数据源：

| 数据源 | 内容 | 特点 |
|---|---|---|
| **raw（原始文本）** | 用户粘贴的小说全文 | 无结构，AI需自己分析结构，耗token多，质量一般 |
| **decon（拆书数据）** | 拆书模块产出的五维结构化数据 | 已有结构/角色/世界观/主题/情节五维分析，质量高，省token |

**source_type 是告诉后端用哪套蒸馏策略的开关**：
- `source_type="raw"` → 后端用原始文本蒸馏提示词
- `source_type="decon"` → 后端用拆书数据蒸馏提示词（基于已有五维结构）

// storyboard.html 新增统一封装
async function safeFetchJSON(url, opts) {
  const r = await fetch(url, opts);
  if (!r.ok) throw new Error(`HTTP ${r.status}`);
  const ct = r.headers.get('content-type') || '';
  if (!ct.includes('application/json')) {
    throw new Error('服务器返回非JSON响应，可能为错误页面');
  }
  return r.json();
}
